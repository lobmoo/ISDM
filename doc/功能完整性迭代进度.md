## M2 交付内容

## M7 交付内容

- 定向 Command：按 `NodeId` 找到在线 peer，数据面单播发送。

- 发送端 pending 表：`command_retry_interval` 重发，deadline 后回调 `kTimeout`。
- 接收端结果缓存：`(source, request_id)` 去重，抑制重试导致的重复执行。
- metrics：`tx_commands / rx_commands / tx_command_retries / tx_command_acks / rx_command_acks / rx_command_duplicates / command_timeouts`。
- 已知限制：handler 在目标数据线程执行；无 exactly-once、命令历史、广播命令、认证/TLS。

## M6 交付内容

- 新增 `EventId` / `EventSeverity` / `EventMetadata`；事件线协议 `kEvent=14`、`kEventReplayRequest=15`。
- `Node::publish_event(_typed/_dynamic)`；`subscribe_event` / `subscribe_event_typed<T>` / `subscribe_event_dynamic` / `subscribe_all_events`。
- `EventMetadata` 同时带 `source_timestamp` 与 `receive_timestamp`；`(source,event_id)` 去重。
- 有界 `EventStore`：默认 10000 条 / 64MB / 300s；`request_event_replay(type_id, since, max_events)`。
- Replay 只由本地发布过该事件的节点提供；中继节点不重放收到的事件，避免 source 变化导致去重失效。
- per-TypeId watermark：`max observed source timestamp - event_watermark_lateness`，回调 + 查询。
- metrics：`tx_events / rx_events / rx_event_duplicates / rx_event_replays`。
- 已知限制：无 ACK/重传/exactly-once；事件历史被驱逐后无法 replay；watermark 不是完整性保证；事件先于 schema 到达时 typed/dynamic 可能错过（raw 可收到）；replay 请求无重试/End 标记。

## M4 交付内容

- 帧头 `sequence` 每个 data/delta 帧递增；接收端按 source 统计缺口/重复。
- SchemaRequest/SnapshotRequest 进入 pending 表：200ms/500ms 重试，最多 3 次；响应/`SnapshotBegin` 按 `request_id` 清除 pending。
- `Node::stop()` 发送 GOODBYE；对端立即移除 peer 并触发离线回调；`known_peers_` 在 peer 消失/离线时清理，重连会重新推 schema。
- 有界状态：ObjectStateStore、snapshot staging、fragment pending、schema request 时间表都有上限/清理。
- `two_process` publisher 改为等待 peer，而不是固定 400ms。
- 已知限制：没有独立 ACK/NACK（响应即 ACK）；快照请求重试发往原始 peer 列表；dedup 主要靠 timestamp（sequence 已写入帧但对象级 sequence 仍为 0）；store 满时驱逐是 O(n) 扫描（M6）。

## M3 交付内容

- `ObjectStateStore`：O(1) 全量状态、按 timestamp 有界驱逐、按 timestamp/sequence dedup。
- 原子快照：`SnapshotBegin/Chunk/End`、每对象 `schema_id/timestamp/sequence`、接收端 staging、`staged_count == expected_count` 与 chunk 覆盖校验、End 后统一应用。
- Snapshot staging 按 `(source, snapshot_id)` 隔离；缺块/超时/超限丢弃，不暴露半成品。
- Delta baseline 用 store 最新 full 值；`publish_delta_typed<T>`；无 base 时回退 full publish。
- 分片按 `(source, frame_id)` 隔离，修复多 publisher 同 frame_id 串包；限制总数/总字节。
- 已知限制：sequence 暂为 0，dedup 主要靠 timestamp（M4 补 sequence）；快照对象超过单 chunk 上限会被跳过；store 驱逐在达到上限时是 O(n) 扫描（M6 优化）；快照请求重试/ACK 留到 M4。

状态取值：未开始 / 进行中 / 已完成 / 阻塞 / 延后。
