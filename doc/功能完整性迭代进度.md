## M2 交付内容

- 帧头 `schema_id` 精确选择 descriptor；packed 缺失时按 tag 兼容解码 + 限速 `SchemaRequest`；fixed-raw 缺失时丢弃 + 请求。
- `SchemaRequest/SchemaResponse` 携带 `request_id/schema_id/version`；Node 处理请求并回精确 schema。
- `schema_decode_compatible`（读取方向，重叠字段类型一致）与 `schema_evolution_compatible`（注册方向，严格末尾追加）。
- `register_type_typed` 要求新版本号更高且 append-only 兼容；不兼容拒绝。
- metrics：`rx_schema_fallback/rx_schema_miss/rx_schema_mismatch/tx_schema_requests`。
- 已知限制：SchemaRequest 重试/ACK 留到 M4；fixed-raw 当前帧在 schema 缺失时丢弃，靠后续快照恢复（M3）；compatibility 以 TypeId 为逻辑身份，不比较 C++ 类型名。

## M4 交付内容

- 帧头 `sequence` 每个 data/delta 帧递增；接收端按 source 统计缺口/重复。
- SchemaRequest/SnapshotRequest 进入 pending 表：200ms/500ms 重试，最多 3 次；响应/`SnapshotBegin` 按 `request_id` 清除 pending。
- `Node::stop()` 发送 GOODBYE；对端立即移除 peer 并触发离线回调；`known_peers_` 在 peer 消失/离线时清理，重连会重新推 schema。
- 有界状态：ObjectStateStore、snapshot staging、fragment pending、schema request 时间表都有上限/清理。
- `two_process` publisher 改为等待 peer，而不是固定 400ms。
- 已知限制：没有独立 ACK/NACK（响应即 ACK）；快照请求重试发往原始 peer 列表；dedup 主要靠 timestamp（sequence 已写入帧但对象级 sequence 仍为 0）；store 满时驱逐是 O(n) 扫描（M6）。

## M3 交付内容

- `ObjectStateStore`：O(1) 全量状态、按 timestamp 有界驱逐、按 timestamp/sequence dedup。
- 原子快照：`SnapshotBegin/Chunk/End`、每对象 `schema_id/timestamp/sequence`、接收端 staging、`staged_count == expected_count` 与 chunk 覆盖校验、End 后统一应用。
- Snapshot staging 按 `(source, snapshot_id)` 隔离；缺块/超时/超限丢弃，不暴露半成品。
- Delta baseline 用 store 最新 full 值；`publish_delta_typed<T>`；无 base 时回退 full publish。
- 分片按 `(source, frame_id)` 隔离，修复多 publisher 同 frame_id 串包；限制总数/总字节。
- 已知限制：sequence 暂为 0，dedup 主要靠 timestamp（M4 补 sequence）；快照对象超过单 chunk 上限会被跳过；store 驱逐在达到上限时是 O(n) 扫描（M6 优化）；快照请求重试/ACK 留到 M4。

状态取值：未开始 / 进行中 / 已完成 / 阻塞 / 延后。
