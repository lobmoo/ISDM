# ISDM 架构设计与开发计划

> **基于原设计文档的架构细化与实施方案**

---

## 一、设计文档评审

### 1.1 核心优势
原设计文档思路清晰，核心理念"Object First"和"Schema与Data分离"非常正确，这是解决60万+数据点的关键。

### 1.2 需要补充的关键问题

#### 问题1：TypeID/FieldID分配策略不够具体
**问题描述：**
文档提到使用Hash(name)生成ID，但Hash冲突的具体处理机制不明确。

**建议方案：**
```cpp
// 分层ID设计
TypeID = uint32_t
  [31:24] = Namespace (8 bits) -> 256个命名空间
  [23:0]  = Local Type ID (24 bits) -> 每个命名空间16M类型

// 冲突处理
1. 编译期：通过代码生成工具检测冲突
2. 运行期：Schema Registry维护Name->ID双向映射，检测冲突
3. 冲突时：返回错误，要求用户显式指定FieldID
```

#### 问题2：Wire Format缺少精确定义
**问题描述：**
文档多处提到Wire Format但未给出字节级布局。

**建议补充：**
```
Frame Header (固定32字节):
+0    uint32_t  magic           // 0x49534450 ("ISDP")
+4    uint8_t   version_major
+5    uint8_t   version_minor
+6    uint16_t  header_length
+8    uint32_t  payload_length
+12   uint32_t  flags
+16   uint64_t  sequence
+24   uint64_t  timestamp_ns
```

#### 问题3：编译期反射实现方案缺失
**问题描述：**
文档提到REGISTER_TYPE(Motor)，但未说明如何实现编译期结构体反射。

**建议方案：**
```cpp
// 方案A：宏 + 模板元编程
#define ISDM_STRUCT(Type, ...) \
  template<> struct TypeDescriptor<Type> { \
    static constexpr auto fields = std::make_tuple(__VA_ARGS__); \
  };

// 方案B：使用Clang LibTooling生成代码
// motor.h -> motor.isdm.h (自动生成)

// 方案C：C++20 Reflection TS（未来）

#### 问题4：Shared Memory并发模型不够具体
**问题描述：**
提到Lock-free Ring Buffer，但多Reader场景下的具体实现细节不明确。

**建议方案：**
```cpp
// SPSC: Single Producer, Single Consumer
// 使用Sequence + Memory Barrier即可

// MPSC: Multiple Producer, Single Consumer  
// Producer侧需要CAS竞争slot

// MPMC: Multiple Producer, Multiple Consumer
// 推荐使用：每个Consumer独立的ReadPosition
// Producer写入时更新WritePosition
// Consumer各自追踪自己的ReadPosition
struct RingBufferSlot {
  std::atomic<uint64_t> sequence;
  uint32_t length;
  char data[MAX_FRAME_SIZE];
};
```

#### 问题5：Schema Evolution的兼容性规则缺失
**问题描述：**
提到支持Schema Version，但未明确哪些变更是兼容的。

**建议规则：**
```
向后兼容（Backward Compatible）：
✓ 添加新字段（末尾）
✓ 删除Optional字段
✗ 删除Required字段
✗ 改变字段类型
✗ 改变字段顺序

向前兼容（Forward Compatible）：
✓ 旧Subscriber能处理新Publisher（忽略未知字段）

建议：
1. FieldID永久绑定，不可复用
2. 新增字段必须有默认值
3. 删除字段通过Deprecated标记，保留FieldID
```

### 2.2 核心模块设计

#### 2.2.1 Type System (core/type/)

**职责：** 定义所有基础类型和复合类型

```cpp
// core/type/primitive_type.h
enum class PrimitiveType : uint8_t {
  kBool = 1,
  kInt8, kUint8,
  kInt16, kUint16,
  kInt32, kUint32,
  kInt64, kUint64,
  kFloat32, kFloat64,
  kString,
  kTimestamp,
};

// core/type/type_descriptor.h
class TypeDescriptor {
 public:
  uint32_t type_id() const;
  uint32_t version() const;
  TypeKind kind() const;
  std::string_view name() const;
  span<const FieldDescriptor> fields() const;
  
  // 编译期类型计算
  size_t size() const;
  size_t alignment() const;
  
 private:
  uint32_t type_id_;
  uint32_t version_;
  TypeKind kind_;
  std::string name_;
  std::vector<FieldDescriptor> fields_;
};

// core/type/field_descriptor.h
struct FieldDescriptor {
  uint32_t field_id;
  std::string name;
  uint32_t type_id;
  uint32_t offset;    // Wire format offset
  uint32_t size;
  FieldFlags flags;   // Optional, Repeated, etc.
};
```

**依赖：** 无（基础模块）

#### 2.2.2 Schema Registry (core/schema/)

**职责：** 管理所有Type和Schema，支持查询和更新

```cpp
// core/schema/schema_registry.h
class SchemaRegistry {
 public:
  // 注册类型（编译期生成的TypeDescriptor）
  Status RegisterType(const TypeDescriptor& descriptor);
  
  // 查询
  const TypeDescriptor* GetType(uint32_t type_id) const;
  const TypeDescriptor* GetType(std::string_view name) const;
  
  // Schema序列化
  Status SerializeSchema(uint32_t type_id, Buffer* output);
  Status DeserializeSchema(const Buffer& input, TypeDescriptor* output);
  
  // 版本管理
  bool IsCompatible(uint32_t type_id, uint32_t version) const;
  
 private:
  // 使用concurrent_flat_map实现lock-free读取
  struct TypeEntry {
    TypeDescriptor descriptor;
    std::atomic<uint64_t> ref_count;
  };
  
  ConcurrentHashMap<uint32_t, TypeEntry> types_by_id_;
  ConcurrentHashMap<std::string, uint32_t> types_by_name_;
};
```

**依赖：** Type System

#### 2.2.3 Object Manager (core/object/)

**职责：** 管理对象实例，维护ObjectID到数据的映射

```cpp
// core/object/object_store.h
class ObjectStore {
 public:
  // 创建对象
  ObjectHandle CreateObject(uint32_t type_id, uint64_t object_id);
  
  // 访问对象
  ObjectView GetObject(uint64_t object_id) const;
  MutableObjectView GetMutableObject(uint64_t object_id);
  
  // 删除对象
  Status DeleteObject(uint64_t object_id);
  
  // Dirty tracking
  void MarkDirty(uint64_t object_id, uint32_t field_id);
  std::vector<uint64_t> GetDirtyObjects();
  void ClearDirty();
  
 private:
  struct ObjectSlot {
    uint32_t type_id;
    uint64_t object_id;
    std::atomic<uint32_t> dirty_bitmap;
    void* data;  // 指向实际数据（从MemoryPool分配）
  };
  
  // 使用flat array + hash index
  std::vector<ObjectSlot> objects_;
  ConcurrentHashMap<uint64_t, uint32_t> object_index_;
  MemoryPool* pool_;
};
```

**依赖：** Type System, Schema Registry, Memory Manager

#### 2.2.4 Memory Manager (runtime/memory/)

**职责：** 高性能内存分配，避免运行期malloc/free

## 四、开发步骤（分阶段实施）

### Phase 1: 基础框架 (2-3周)

**目标：** 建立类型系统和基础API

**任务清单：**
```
[ ] 1.1 搭建CMake构建系统
    - 配置C++17/20
    - 集成第三方库（gtest, benchmark, spdlog）
    - 设置编译选项（-Wall -Wextra -O3）

[ ] 1.2 实现Type System
    - PrimitiveType枚举
    - TypeDescriptor类
    - FieldDescriptor结构
    - 基础类型size和alignment计算

[ ] 1.3 实现Schema Registry
    - ConcurrentHashMap（基于abseil或自实现）
    - RegisterType/GetType接口
    - 简单的Schema序列化（先用JSON，后续改二进制）

[ ] 1.4 实现Object Store
    - MemoryPool基础实现
    - ObjectStore基础CRUD
    - 简单的Dirty Tracking（bitmap）

[ ] 1.5 单元测试
    - Type System测试
    - Schema Registry测试
    - Object Store测试
```

**验收标准：**
```cpp

  float speed;

Node node;

### Phase 2: 协议层基础 (2-3周)

**目标：** 实现Wire Protocol和基础编解码

**任务清单：**
```
[ ] 2.1 定义Wire Format
    - Frame Header定义（32字节）
    - MessageType枚举
    - Flags定义
    - 字节序处理（Little Endian）

[ ] 2.2 实现Codec
    - Encoder: 基础类型编码
    - Decoder: 基础类型解码
    - Struct编码（fixed layout）
    - Array编码

[ ] 2.3 实现Frame Builder/Parser
    - FrameBuilder: 构建DATA frame
    - FrameParser: 解析frame
    - CRC32C校验

[ ] 2.4 单元测试 + Fuzz测试
    - 编解码正确性测试
    - 边界条件测试（空数据、最大size）
    - Fuzz测试（随机输入）
```

### 6.2 Lock-free Ring Buffer实现

```cpp
// runtime/memory/ring_buffer.h
template<typename T, size_t Capacity>
class SPSCRingBuffer {
 public:
  bool Push(const T& item) {
    uint64_t write_pos = write_pos_.load(std::memory_order_relaxed);
    uint64_t next_write = write_pos + 1;
    
    if (next_write == read_pos_.load(std::memory_order_acquire)) {
      return false; // Full
    }
    
    buffer_[write_pos % Capacity] = item;
    write_pos_.store(next_write, std::memory_order_release);
    return true;
  }
  
  bool Pop(T* item) {
    uint64_t read_pos = read_pos_.load(std::memory_order_relaxed);
    
    if (read_pos == write_pos_.load(std::memory_order_acquire)) {
      return false; // Empty
    }
    
    *item = buffer_[read_pos % Capacity];
    read_pos_.store(read_pos + 1, std::memory_order_release);
    return true;
  }
  
 private:
  std::array<T, Capacity> buffer_;
  alignas(64) std::atomic<uint64_t> write_pos_{0};
  alignas(64) std::atomic<uint64_t> read_pos_{0};
};
```

### 6.3 Delta Bitmap编码

```cpp
// runtime/delta/bitmap_encoder.h
class BitmapEncoder {
 public:
  // 编码变化bitmap
  static void Encode(const std::vector<bool>& bitmap, Buffer* output) {
    // 方案1：直接bitmap（适合高变化率）
    if (ChangeRate(bitmap) > 0.1) {
      EncodeDenseBitmap(bitmap, output);
      return;
    }
    
    // 方案2：Sparse index（适合低变化率）
    EncodeSparseIndex(bitmap, output);
  }
  
 private:
  static void EncodeDenseBitmap(const std::vector<bool>& bitmap, Buffer* output) {
    // 按64bit打包
    for (size_t i = 0; i < bitmap.size(); i += 64) {
      uint64_t word = 0;
      for (size_t j = 0; j < 64 && i + j < bitmap.size(); j++) {
        if (bitmap[i + j]) {
          word |= (1ULL << j);
        }
      }
      output->Append(&word, sizeof(word));
    }
  }
  
  static void EncodeSparseIndex(const std::vector<bool>& bitmap, Buffer* output) {
    // 只记录变化的index
    std::vector<uint32_t> indices;
    for (size_t i = 0; i < bitmap.size(); i++) {
      if (bitmap[i]) {
        indices.push_back(i);
      }
    }
    
    uint32_t count = indices.size();
    output->Append(&count, sizeof(count));
    output->Append(indices.data(), count * sizeof(uint32_t));
  }
};
```

## 八、核心设计决策总结

### 8.1 原设计文档的优势保留

✓ **Object First而非Variable First** - 这是正确的抽象层次  
✓ **Schema与Data分离** - 避免重复传输元数据  
✓ **Control Plane / Data Plane分离** - 保证实时性  
✓ **Batch优先** - 必须的性能优化  
✓ **Delta机制** - 降低大规模数据开销  
✓ **Zero Configuration Discovery** - 真正解决配置痛点  

### 8.2 架构改进建议

#### 改进1：ID分配策略明确化
```
原方案：Hash(name) -> 可能冲突
改进方案：
  - 编译期：静态分配 + 冲突检测
  - 运行期：Registry双向映射 + 冲突拒绝
  - 分层ID：[Namespace:8bit][LocalID:24bit]
```

#### 改进2：Wire Format精确定义
```
原方案：概念性描述
改进方案：
  - 字节级布局规范
  - Endianness明确（Little Endian）
  - Alignment规则明确
  - 版本演进路径
```

#### 改进3：编译期反射可实现性
```
原方案：REGISTER_TYPE(Motor)
改进方案：
  Phase 1: 宏 + offsetof
  Phase 2: Clang LibTooling代码生成
  Phase 3: C++26 Reflection（未来）
```

#### 改进4：并发模型细化
```
原方案：Lock-free概念
改进方案：
  - SPSC/MPSC/MPMC明确区分
  - Memory Order明确指定
  - Seqlock用于Read-mostly数据
  - RCU用于Schema更新
```

#### 改进5：不依赖DDS
```
原方案：可能受DDS影响
改进方案：
  - 自研协议和Runtime
  - DDS仅作为参考和Adapter
  - 避免Topic爆炸问题

## 十、风险与应对

### 10.1 技术风险

#### 风险1：600K性能目标达不到
**可能原因：**
- CPU性能不足
- 内存带宽瓶颈
- 系统调用开销
- Cache miss严重

**应对措施：**
- Phase 4提前做100K benchmark
- 优先实现Delta减少数据量
- 使用SHM避免系统调用
- Profile驱动优化

#### 风险2：Schema反射实现复杂
**可能原因：**
- C++17反射能力有限
- 嵌套结构复杂
- 跨平台ABI差异

**应对措施：**
- Phase 1用简单宏实现MVP
- Phase 2引入代码生成工具
- 限制第一版仅支持POD类型

#### 风险3：并发正确性难保证
**可能原因：**
- Lock-free实现复杂
- Memory Order错误
- ABA问题

**应对措施：**
- 使用成熟的concurrent库（abseil）
- TSan检测race condition
- 充分的单元测试

#### 风险4：网络环境复杂性
**可能原因：**
- Multicast被禁用
- 跨网段通信
- 防火墙限制

**应对措施：**
- 支持Seed Node Discovery
- 支持Static配置
- 提供网络诊断工具

### 10.2 工程风险

#### 风险1：时间估算不准
**应对：**
- 按Phase迭代，每个Phase有明确验收标准
- 定期Review进度

### 11.1 MVP Demo目标

**功能：**
```

### 11.2 Demo代码示例

**motor.h:**
```cpp
#pragma once
#include <cstdint>

namespace demo {

struct Motor {
  float speed;
  float current;
  float voltage;
  uint32_t status;
};

} // namespace demo

// 注册类型
#include "isdm/reflect.h"
ISDM_STRUCT(demo::Motor,
  ISDM_FIELD(demo::Motor, speed),
  ISDM_FIELD(demo::Motor, current),
  ISDM_FIELD(demo::Motor, voltage),
  ISDM_FIELD(demo::Motor, status)
)
```

**publisher.cc:**
```cpp
#include "motor.h"
#include "isdm/node.h"
#include <iostream>
#include <thread>

int main() {
  // 创建节点
  isdm::Node node("publisher");
  
  // 创建Publisher
  auto publisher = node.CreatePublisher<demo::Motor>();
  
  std::cout << "Publisher started. Sending data...\n";
  
  // 循环发送
  for (int i = 0; i < 1000; i++) {
    demo::Motor motor;
    motor.speed = 1000.0f + i;
    motor.current = 20.0f + i * 0.01f;
    motor.voltage = 380.0f;
    motor.status = i % 2;
    
    publisher->Publish(motor);
    
    if (i % 100 == 0) {
      std::cout << "Sent " << i << " motors\n";
    }
    
    std::this_thread::sleep_for(std::chrono::milliseconds(10));
  }
  
  std::cout << "Done!\n";
  return 0;
}
```

**subscriber.cc:**
```cpp
#include "motor.h"
#include "isdm/node.h"
#include <iostream>
#include <atomic>

int main() {
  // 创建节点
  isdm::Node node("subscriber");
  
  std::atomic<int> count{0};
  
  // 创建Subscriber
  auto subscriber = node.CreateSubscriber<demo::Motor>(
      [&count](const demo::Motor& motor) {
        count++;
        if (count % 100 == 0) {
          std::cout << "Received " << count << " motors, "
                    << "latest: speed=" << motor.speed
                    << " current=" << motor.current << "\n";
        }
      });
  
  std::cout << "Subscriber started. Waiting for data...\n";
  
  // 等待接收
  std::this_thread::sleep_for(std::chrono::seconds(30));
  
  std::cout << "Total received: " << count << "\n";
  return 0;
}
```

#include <string>
#include <vector>

class FieldDescriptor;

 public:

### 13.3 错误处理

```cpp
// 使用Status返回错误
class Status {
 public:
  static Status OK() { return Status(); }
  static Status Error(std::string msg) { return Status(std::move(msg)); }
  
  bool ok() const { return error_msg_.empty(); }
  const std::string& message() const { return error_msg_; }
  
 private:
  explicit Status(std::string msg = "") : error_msg_(std::move(msg)) {}
  std::string error_msg_;
};

// 使用示例
Status RegisterType(const TypeDescriptor& desc) {
  if (desc.typeId() == 0) {
    return Status::Error("Invalid type ID");
  }
  
  if (types_.count(desc.typeId()) > 0) {
    return Status::Error("Type ID already registered");
  }
  
  types_[desc.typeId()] = desc;
  return Status::OK();
}

// 调用方检查
auto status = registry.RegisterType(desc);
if (!status.ok()) {
  LOG(ERROR) << "Failed to register type: " << status.message();
  return;
}
