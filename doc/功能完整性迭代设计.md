## 1. 背景与目标

当前代码是一个可运行的端到端 MVP：编译期反射 + SchemaRegistry + UDP 发现/同步 + 单对象/批量传输 + 字段级 Delta + 分片 + 128 项单元测试。但它仍有一个根本限制：**只支持扁平 POD 结构**（[reflect.h](../src/isdm/reflect.h) 的 `PrimitiveOf` 只有基础类型），并且 Snapshot/重连/多 publisher 场景存在一致性缺口。

本迭代的目标不是追 600K 性能，而是把**数据建模能力和状态恢复语义**补完整，为后续性能迭代提供正确的数据面。按依赖顺序分四个工作流：

1. **M1 复杂类型**：嵌套 struct、定长数组、变长 Sequence、String；对应的反射、Schema、编解码、typed/dynamic API。
2. **M2 Schema 版本与演进**：wire 上携带 `schema_id`，SchemaRequest/Response，兼容规则，旧读者忽略未知字段。
3. **M3 快照/重连一致性**：原子 Snapshot、实时流与快照去重、Delta baseline、分片按 peer 隔离。
4. **M4 可靠性**：序号/缺口检测、请求重试/ACK、Goodbye、有界状态。

**成功标准**：一个包含嵌套结构、定长数组、变长序列和字符串的对象，可以在两个进程之间自动同步 Schema、发布、接收、按类型解码和按字段名通用解码；升级字段后旧/新读者按明确规则工作；晚加入/断线重连的订阅者能拿到一致的全量状态；多 publisher 的分片不串包，对象所有权按单写者语义（§12）。

## 2. 范围与非目标

### 2.1 本迭代范围

- M1：嵌套 struct（值成员）、一维定长数组（`std::array<T,N>` / C 数组）、一维 `std::vector<T>`、`std::string`；元素类型限基础类型（M1 不支持 struct 数组/序列）。
- M1：保留 fixed-layout 的原始字节零拷贝快路径；复杂类型走 descriptor 驱动的 packed 编码。
- M2：同一 TypeId 多版本共存；帧头 `schema_id` 精确选择 descriptor；SchemaRequest/Response；追加字段兼容。
- M3：Snapshot begin/chunk/end；接收端暂存后原子应用；按对象去重；Delta 更新 baseline；分片 key 加来源 peer。
- M4：帧序号与缺口统计；Schema/Snapshot 请求重试；Goodbye；状态缓存有界。

### 2.2 非目标（本迭代明确不做）

- **不追 600K/50Hz 性能目标**；不做 SHM、zero-copy 共享内存、NUMA、SIMD、AF_XDP、RDMA。
- **不做复杂类型的 Batch/Delta**：`publish_batch` / `publish_delta` 在 M1–M4 仅支持 `kFixedRaw` 类型；复杂类型用整对象发布。复杂类型批量/增量放到后续性能迭代。
- **不做 struct 的数组/序列**（`std::vector<Position>`、`Position[8]`）；M1 只支持基础类型元素。
- **不做非零默认值**：M2 缺失字段按零/空初始化；显式默认值后续迭代。
- **不做压缩、加密、TCP、Schema 兼容的跨编译器 ABI 保证**。
- **不做 v0.1 节点互操作**：wire 协议升级到 v0.2，所有节点需一起升级（见 §10 决策）。

### 2.3 协议版本决策

- Header `kVersionMinor` 从 1 升到 2；Schema wire 增加 `schema_wire_version = 2`。
- **Packed 从 M1 起就使用带 tag 的格式**（`u32 field_id, u32 length, value`），M2 不替换 packed wire 格式，只增加兼容规则和请求流程；因此不存在“M1 无 tag、M2 有 tag”的过渡版本，`schema_wire_version` 保持 2。
- 接收端收到非 v0.2 的帧直接丢弃并计 `rx_version_mismatch`；不做双解码。
- 理由：当前没有生产部署，双版本会显著增加 M1/M2 的实现和测试面；先保证新语义正确。
- 如果后续必须兼容 v0.1，可在 `parse_frame` 前增加一个 v0.1 分支，本文不做。

## 3. 总体设计

### 3.1 两种载荷布局

| 布局 | 判定 | 线上载荷 | 解码 |
|---|---|---|---|
| `kFixedRaw` | 所有叶子字段都是定长（基础类型、定长基础数组、只含定长字段的嵌套 struct） | `sizeof(T)` 原始字节（含 padding） | 零拷贝 `memcpy`/`DataView`，保持现有行为 |
| `kPacked` | 至少一个叶子是 String/Sequence，或嵌套 struct 展开后含变长字段 | 按 descriptor 字段顺序的 packed 编码 | descriptor 驱动逐字段解码；typed 路径用本地 codec |

`TypeDescriptor.fixed_size` 始终记录 `sizeof(T)`（本地 C++ 对象大小），用于 typed codec 和 fixed-raw 校验；packed 的线上大小由消息的 payload length 决定，不能用 `fixed_size` 判断。

### 3.2 嵌套 struct 采用“扁平展开”

M1 不引入命名嵌套类型/递归 descriptor，而是在 `describe<T>` 时把嵌套值成员的叶子字段展开到父 descriptor：

```
struct Position { float x; float y; float z; };
struct Motor { Position position; float speed; };
```

生成的字段为：

```
position.x  offset=offsetof(Motor, position) + offsetof(Position, x)  size=4
position.y  ...
position.z  ...
speed       ...
```

优点：不需要嵌套 TypeId、嵌套 Schema 请求、递归 registry；现有 flat Schema wire 只需加字段。缺点：同一嵌套类型被多个父类型使用时 schema 会重复；字段改名会改变 FieldID。M1 接受这个取舍，命名嵌套类型留到后续。

`field_id` 使用 **点分字段名的 FNV-1a 32-bit 哈希**（例如 `position.x`），保证字段重排/中间插入不影响 ID；同一 descriptor 内出现重复 ID 时 `register_type` 拒绝。哈希为 0 时改为 1。字段改名视为不兼容变更。

### 3.3 反射与字段展开

`ISDM_STRUCT` / `ISDM_FIELD` 的**用户写法不变**，内部从“每个成员一个 FieldSpec”改为“每个 `ISDM_FIELD` 展开成一个 `std::vector<FieldSpec>`，再拼接”：

```cpp
#define ISDM_FIELD(Type, member) \
  ::isdm::detail::ExpandField<decltype(Type::member)>(#member, offsetof(Type, member))
```

`ExpandField<T>` 的规则：

- 基础类型：一个 spec，`kind=PrimitiveOf<T>::value`，`element_kind` 同，`element_size=sizeof(T)`，`size=sizeof(T)`，`variable=false`。
- `std::string`：一个 spec，`kind=kString`，`element_kind=kUint8`，`element_size=1`，`size=0`，`variable=true`。
- `std::vector<E>`：一个 spec，`kind=kSequence`，`element_kind=PrimitiveOf<E>::value`，`element_size=sizeof(E)`，`size=0`，`variable=true`；M1 `static_assert` E 是基础类型。
- `std::array<E,N>` / `E[N]`：一个 spec，`kind=kArray`，`array_length=N`，`element_kind=PrimitiveOf<E>::value`，`element_size=sizeof(E)`，`size=N*sizeof(E)`，`variable=false`；M1 `static_assert` E 是基础类型。
- 已反射的 struct：取 `TypeTraits<T>::field_specs()`，对每个叶子做
  - `name = prefix + "." + leaf.name`
  - `offset += base_offset`
  - 其余字段/codec 原样保留。
- 其他类型（指针、enum、map、未 `ISDM_STRUCT` 的 struct）：`static_assert` 带清晰消息，编译期失败。

`FieldSpec` 增加本地 codec 函数指针（不进入 wire）：

```cpp
struct FieldSpec {
  const char* name;
  std::size_t offset;
  std::size_t size;
  TypeKind kind;
  TypeKind element_kind;
  std::size_t element_size;
  std::uint32_t array_length;
  bool variable;
  bool (*encode)(const void* base, std::size_t offset, ByteWriter&);
  bool (*decode)(ByteReader&, void* base, std::size_t offset);
};
```

`encode/decode` 由 `CodecFor<T>` 模板生成：基础类型 memcpy，定长数组按 N 个元素写/读，String 写 `u32 length + bytes`，Sequence 写 `u32 count + count*element_size`。嵌套 struct 已经被展开，不需要 StructCodec。所有长度在 decode 时做边界检查，且受 `kMaxFrame`（64KB）限制。

### 3.4 `TypeDescriptor` / `FieldDescriptor` 扩展

为了保持现有手写 descriptor 的聚合初始化可编译，新字段**追加在末尾**；0 值有明确含义：

```cpp
enum class TypeLayout : std::uint8_t { kFixedRaw = 0, kPacked = 1 };

struct FieldDescriptor {
  // 现有字段保持顺序
  FieldId field_id;
  std::uint32_t name_offset;
  TypeKind kind;
  TypeId referenced_type_id;
  std::uint32_t offset;
  std::uint32_t size;
  std::uint32_t array_length;
  // 新增
  TypeKind element_kind;      // 0 = 与 kind 相同（兼容手写 descriptor）
  std::uint32_t element_size; // 0 = 由 size/array_length 推断
  std::uint32_t flags;        // bit0 = variable；0 = 按 kind 推断
};

struct TypeDescriptor {
  // 现有字段保持顺序
  TypeId type_id;
  Version version;
  TypeKind kind;
  std::uint32_t name_offset;
  std::uint32_t fixed_size;
  std::uint32_t field_count;
  const FieldDescriptor* fields;
  const char* name_table;
  // 新增
  TypeLayout layout;          // 0 = kFixedRaw
};
```

`element_kind==0` 时视为 `kind`；`element_size==0` 时，定长字段用 `size`，数组用 `size/array_length`；`flags==0` 时，`kind==kString/kSequence` 视为 variable。

### 3.5 编解码

新增 `src/isdm/codec/object_codec.h`：

```cpp
struct DynamicField {
  std::string name;
  TypeKind kind;
  TypeKind element_kind;
  std::uint32_t element_size;
  std::uint32_t count;   // array/sequence/string 的元素数；普通字段为 0
  DataView bytes;        // 指向 payload 内，回调返回后失效
};

struct DynamicObject {
  TypeId type_id;
  Version version;
  const TypeDescriptor* descriptor;
  std::vector<DynamicField> fields;
};

class ObjectCodec {
 public:
  // typed：需要本地 ReflectedType（descriptor + codecs）
  static bool encode(const ReflectedType& type, const void* value, ByteWriter& out);
  static bool decode(const ReflectedType& type, ByteReader& in, void* value);

  // dynamic：只需要 descriptor；用于通用订阅/非 C++ 生产者
  static bool encode_dynamic(const TypeDescriptor& desc, const DynamicObject& obj,
                             ByteWriter& out);
  static bool decode_dynamic(const TypeDescriptor& desc, DataView payload,
                             DynamicObject& out);
};
```

- `kFixedRaw`：`encode/decode` 走原始字节；`decode_dynamic` 用 `field.offset/size` 生成 view。
- `kPacked`：payload 以一个 packed 头开始，然后按 descriptor 字段顺序写字段 tag：
  - packed 头：`u16 magic = 0x504B ("PK"), u16 field_count`；
  - 每个字段：`u32 field_id, u32 length, value`；`length` 是 value 的字节数（定长字段等于 `size`；String/Sequence 等于 `count * element_size`）。
  - 接收端可以跳过未知 `field_id`（长度已知），并对缺失字段零默认；因此 M1 的 packed 格式已经为 M2 的追加字段兼容做好准备。`packed_format_version = 1` 参与指纹。
  - tag 的 8B/字段开销只出现在复杂类型冷路径；fixed-raw 不受影响。
- `decode_dynamic` 对 String/Sequence 读 tag 的 `u32 length`，校验 `length <= remaining`，再生成 view；`count = length / element_size` 写入 `DynamicField`（String 的 element_size=1，count=字节数）。
- `DynamicObject` 的 `DataView` 指向当前接收缓冲区；回调内有效，不能跨回调保存。需要持有时由调用方拷贝。
- 编码失败（缓冲区不足、未知字段、长度超限）返回 false，不抛异常。typed decode 中 `std::string/vector` 的分配失败按标准库行为处理；这是冷路径，不承诺零分配。

### 3.6 Node API

新增/调整（`src/isdm/node.h`）：

```cpp
// 注册：构建 ReflectedType，注册 descriptor，并缓存本地 codec 表
template <typename T>
bool register_type_typed(TypeId type_id, Version version = 1);

// typed 发布/订阅：支持 fixed 和 packed；不再要求 trivially copyable
template <typename T>
bool publish_typed(ObjectId object_id, TypeId type_id, const T& value, Timestamp ts = 0);

template <typename T>
void subscribe_typed(TypeId type_id, std::function<void(ObjectId, const T&)> cb);

// dynamic：不依赖 C++ 类型
bool publish_dynamic(ObjectId object_id, TypeId type_id, const DynamicObject& obj,
                     Timestamp ts = 0);
void subscribe_dynamic(TypeId type_id, std::function<void(ObjectId, const DynamicObject&)> cb);

// 现有原始接口保留；新增 schema_id 重载给 packed/多版本使用
bool publish(ObjectId, TypeId, DataView, Timestamp = 0);
bool publish(ObjectId, TypeId, DataView, Timestamp ts, SchemaId schema_id);

// Delta：推荐使用 store 作为 baseline 的 typed 版本
template <typename T>
bool publish_delta_typed(ObjectId object_id, TypeId type_id, const T& new_value,
                         Timestamp ts = 0);
```

行为：

- `publish_typed<T>` 从 `typed_types_` 取 `ReflectedType`；若没有，先 `describe<T>` 并校验 fingerprint 与已注册 descriptor 一致，然后缓存。编码后设置 `header.schema_id = fingerprint(desc)`。固定类型走 raw，复杂类型走 packed。
- `subscribe_typed<T>` 同样取/建本地 `ReflectedType`；回调收到 payload 后按 `schema_id` 校验（M2 起严格；M1 若 `schema_id==0` 则用本地 codec 尝试解码），失败计 `rx_decode_errors` 并跳过。
- `publish_dynamic` 用 `registry().find(type_id)` 的 descriptor；找不到返回 false。packed 的缺失字段按零默认（M1 起就支持，因为 tag 格式已就位）。
- `publish_batch` / `publish_delta` 在类型 `layout==kPacked` 时返回 false，并计 `tx_unsupported_layout`；固定类型行为不变。
- `publish` 4 参数版本把 `schema_id` 设为 0，接收端回退到 `find(type_id)` 最新版本；**packed/多版本场景必须使用 5 参数重载**，并提供精确 `schema_id`，payload 必须是 tagged packed 格式。原始 packed payload 的编码责任在调用方。
- `publish_delta_typed<T>` 以 ObjectStateStore 的最新 full 值为补丁基准；没有 baseline 时退化为 full publish。旧 `publish_delta(old,new)` 保留兼容，但标注为“调用方保证 old 与订阅端 baseline 一致”，内部仍以 store base 为准并做长度/指纹校验，不一致时回退 full publish。
- `subscribe`（原始 `DataView` 回调）保留；`subscribe_dynamic` 在内部用 descriptor 解码后调用。
- 线程安全：`typed_types_` 用 `std::shared_mutex` 保护；推荐在 `start()` 前注册，但运行时注册也应安全。

### 3.7 Schema wire v0.2

`src/isdm/protocol/schema_wire.h` 的格式升级：

```
u16 magic = 0x5343
u8  schema_wire_version = 2
u8  layout
u32 type_id
u32 version
u8  kind
str type_name
u32 fixed_size
u32 field_count
repeat field_count:
  u32 field_id
  str field_name
  u8  kind
  u8  element_kind
  u32 referenced_type_id
  u32 offset
  u32 size
  u32 array_length
  u32 element_size
  u32 flags
```

- `SchemaResponse` 外层 magic/kind 不变。
- `encode_schema` 校验 `fixed_size`、`field_count`、name table、layout 合法；`decode_schema` 做所有长度/计数边界检查。
- `SchemaRegistry::fingerprint` 扩展为“线上 schema 指纹”：
  - 纳入：type_id、version、kind、layout、packed_format_version、fixed_size、field_count、每个字段的 field_id/kind/element_kind/element_size/array_length/size/name；
  - **字段顺序**：按 descriptor 顺序纳入，不排序；packed 的字段顺序参与编码，重排视为不兼容。
  - `kFixedRaw` 额外纳入 offset（因为线上就是原始字节布局）；
  - `kPacked` **不纳入 offset/name_offset**（它们是本地 C++/name-table 布局，不影响线上 tag 编码）；
  - `packed_format_version = 1`（tagged）参与指纹；未来 packed 格式变化时递增。
  - 这样同一 packed schema 在不同编译器/ABI 下指纹一致；fixed-raw 指纹仍与 ABI 相关。
- 远程 descriptor 的处理：如果收到的 packed descriptor 与本地的指纹相同，视为同一线上 schema：
  - 若本地已有 descriptor，保留本地（typed codec 需要本地 offset），不替换；
  - 若本地没有，注册远程 descriptor；packed 的 dynamic 解码只用 tag/length，不依赖 offset；
  - 指纹相同但“线上相关字段”不同（哈希碰撞）时拒绝并计 `schema_collision`。
- `SchemaRegistry` 增加 `SchemaId fingerprint(type_id, version)`、`find_by_fingerprint(SchemaId)`；`register_type` 在 arena 中存储 descriptor 时建立指纹索引。

## 4. M1 详细验收

### 4.1 覆盖类型

```cpp
struct Position { float x, y, z; };
struct Motor {
  std::uint32_t id;
  Position position;          // 嵌套 struct，展开为 position.x/y/z
  float samples[8];           // C 数组
  std::array<float, 4> gains; // std::array
  std::vector<float> waveform;// Sequence
  std::string name;           // String
};
```

- `Motor` 为 `kPacked`；`Position` 单独注册为 `kFixedRaw`（如果用户注册它）。
- 纯 `Position`/现有 `reflect_test::Motor` 仍为 `kFixedRaw`，原始字节路径不变。

### 4.2 必测用例

1. `describe<Motor>`：字段数 = 1 + 3 + 1 + 1 + 1 + 1 = 8；字段名 `id`、`position.x/y/z`、`samples`（array_length=8）、`gains`（array_length=4）、`waveform`、`name`；layout=kPacked；每个字段 ID 稳定。
2. fixed-raw 兼容：现有 `reflect_test::Motor` 的 `StructCodec` 往返不变；128 项现有测试保持通过（需要更新的字段 ID 断言除外）。
3. packed typed 往返：`publish_typed<Motor>` → `subscribe_typed<Motor>`，嵌套/数组/序列/字符串逐字段相等；空字符串、空 vector、边界长度（0、1、接近 64KB）都正确。
4. packed dynamic 往返：`publish_dynamic` / `decode_dynamic`，按字段名读取 `position.y`、`waveform` 的 count/bytes、`name`。
5. 跨节点 Schema 同步：subscriber 没有本地 `Motor` 类型，也能用收到的 descriptor 做 dynamic 解码；typed subscriber 用本地 `describe<Motor>` 校验 fingerprint 后解码。
6. 截断/恶意输入：String/Sequence 的 length 超过剩余字节、count 导致乘法溢出、payload 小于固定字段总和、未知 kind、空 payload；不得越界/崩溃，返回 false 并计 `rx_decode_errors`。
7. Fuzz：随机字节输入 `decode_dynamic`/`decode<T>` 不崩溃（扩展现有 `test_fuzz.cc`）。
8. 端到端：`examples/complex_types` 双进程 demo，发布 100 个 `Motor`，两种订阅方式都收到正确值。

### 4.3 性能约束

- fixed-raw 路径不得引入额外拷贝或分配；`publish_typed<Position>` 的路径应接近现有 `publish`。
- packed 路径允许分配/拷贝，但必须在 benchmark 中记录 encode/decode 吞吐，作为后续优化基线；不设硬性指标。
- 单对象 payload 上限仍为 `kMaxFrame`（64KB）；超过时 `publish_typed` 返回 false。

## 5. M2：Schema 版本与演进

### 5.1 wire 上的版本选择

- `Header.schema_id` 由发送端在 typed/dynamic 发布时设置；原始 `publish` 若未设置，接收端回退到 `find(type_id)` 最新版本。
- `dispatch_frame` 把 `header.schema_id` 传给 data/batch/delta 处理器；处理器优先 `find_by_fingerprint(schema_id)`，找不到再按下面的规则处理。
- 接收端收到未知 `schema_id` 时的选择顺序：
  1. `find_by_fingerprint(schema_id)` 命中：直接解码。
  2. `layout==kPacked` 且精确 schema 未命中：尝试用同 TypeId 的最新本地 descriptor 做“tag 兼容解码”——已知 field_id 正常解码，未知 field_id 按 length 跳过，缺失字段零默认。成功则交付，同时限速发送 `SchemaRequest{schema_id}` 缓存精确 schema；失败则丢弃并计 `rx_schema_miss`。
  3. `layout==kFixedRaw` 且精确 schema 未命中：无法安全跳过未知字段，丢弃、计 `rx_schema_miss` 并发送 `SchemaRequest{schema_id}`；等 schema 到达后的下一帧/快照恢复。
- 快照 chunk：`kPacked` 可按上述兼容解码后暂存；`kFixedRaw` 在 schema 到达前不应用快照，丢弃并重试（限速）。无论哪种，End 时都必须校验 `staged_count == expected_count`。
- `rx_schema_miss` 只在“无法解码并丢弃”时递增；兼容解码成功计 `rx_schema_fallback`（可选指标）。

### 5.2 SchemaRequest / SchemaResponse

- `SchemaRequest` payload：`u16 magic=0x5353, u8 kind=Request, u32 request_id, u32 schema_id, u32 type_id, u32 version`。
- `SchemaResponse`：`u16 magic=0x5353, u8 kind=Response, u32 request_id, schema...`；携带完整 descriptor。接收端注册后校验 `fingerprint(desc)==request.schema_id`，不一致则丢弃并计 `schema_mismatch`。
- `request_id` 由请求方生成；响应方原样回显；请求方用 pending 表匹配，超时/重复响应按 request_id 处理（见 M4）。
- 请求重试与去重见 M4；M2 先实现一次请求/响应 + 简单 3 次重试。
- HELLO 的 `schema_fingerprints` 继续作为提示，但不再承担可靠性；注册新类型后更新 advertise 列表（现有 `advertised_fingerprints_` 的时序问题顺带修复）。

### 5.3 兼容规则

- 字段 ID 由点分名哈希决定；字段重命名 = 不兼容。
- 同一 TypeId 下：
  - **允许**：末尾追加新字段（旧读者忽略；新读者零默认）。
  - **禁止**：删除字段、改字段类型/element_kind/element_size、改数组长度、改字段顺序（packed 的字段顺序参与编码）。
  - 删除字段的“可选/保留 ID”机制不在本迭代；删除一律拒绝。
- `kPacked` 从 M1 起就是 tag 格式（§3.5）；旧读者按 length 跳过未知 field_id，新读者对缺失字段零默认。M2 只补兼容规则和请求流程，不更换 packed wire 格式，`schema_wire_version` 保持 2。
- `kFixedRaw` 不做字段级演进：接收端必须拿到发送端的 exact descriptor 才能解码；如果本地已有更新版本，仍按 `schema_id` 找旧 descriptor。也就是说 fixed-raw 的兼容靠“保留旧 schema”，而不是“忽略未知字段”。
- `SchemaRegistry::compatible(old, new)` 返回 `kCompatible / kIncompatible / kNeedsNewType`，供注册时告警；不阻止注册（保留旧版本用于解码），但 `register_type_typed<T>` 若检测到同 TypeId 的不兼容新版本，返回 false。

### 5.4 默认值

- M2 只支持零/空默认：缺失的数值字段填 0，bool false，String 空串，Sequence 空。
- 非零默认值（`ISDM_FIELD_DEFAULT`）后续迭代；在此之前，需要非零默认的业务字段应显式发布或使用 M3 快照。

### 5.5 必测用例

- 旧读者 + 新写者（追加字段）：packed 旧读者按 length 跳过未知 field_id；新读者对缺失字段零默认。
- 类型变更/删除字段/字段重排：`compatible` 返回 incompatible，`register_type_typed` 拒绝。
- 未知 schema_id（packed）：用同 TypeId 最新本地 descriptor 做 tag 兼容解码成功，交付并触发限速 SchemaRequest；不丢帧。
- 未知 schema_id（fixed raw）：丢弃并触发 SchemaRequest；schema 到达后可解码后续帧。
- 指纹稳定性：同一 packed schema 在不同 `offsetof` 下指纹一致，且字段顺序变化会改变指纹；fixed-raw 指纹随 offset 变化。
- 远程 packed descriptor 同指纹但 offset 不同：注册为同一 schema，保留本地 descriptor，dynamic 解码正常。
- 多版本共存：`find(type_id)` 返回最新版本，`find(type_id, version)`/`find_by_fingerprint` 返回精确版本；snapshot chunk 的每个对象带自己的 schema_id。

## 6. M3：快照/重连一致性

### 6.1 原子快照

新增快照控制消息（`src/isdm/protocol/snapshot.h`）：

```
SnapshotBegin: magic, snapshot_id u32, request_id u32, type_id u32,
               expected_count u32, timestamp i64
SnapshotChunk: magic, snapshot_id u32, chunk_index u32, chunk_count u32, count u32,
               count × (object_id u64, schema_id u32, timestamp i64,
                        sequence u64, payload_len u32, payload bytes)
SnapshotEnd:   magic, snapshot_id u32, sent_count u32, chunk_count u32
```

- 每个对象自带 `schema_id/timestamp/sequence`；Begin 不再带单一 `schema_id`，因为同一 TypeId 可能有多版本。`request_snapshot(type_id)` 返回该类型所有版本的当前对象。
- 发送端在 Begin 时**冻结对象集合**：从 store 复制 `(object_id, schema_id, timestamp, sequence, payload)` 到 snapshot buffer；`NodeConfig.snapshot_sender_copy_bytes` 限制大小，超限则中止快照并计 `snapshot_sender_overflow`，不发送不完整快照。
- Chunk 带 `chunk_index/chunk_count`；接收端按 `(source, snapshot_id)` 建 staging，记录已见 chunk_index，收到 Chunk 只暂存、不回调。
- 收到 End 后：
  - 校验 `staged_count == expected_count` 且 chunk_index 覆盖 `0..chunk_count-1`；不满足则丢弃 staging 并计 `snapshot_incomplete`，不把半成品暴露给应用；
  - 对每个 staged 对象，与当前 ObjectStateStore 的 `(timestamp, sequence)` 比较；快照对象不比实时对象新则丢弃；
  - 原子应用到 store，然后统一回调 `dispatch`；
  - 丢弃 staging。
- 超时（默认 5s）、新的 Begin 到达、chunk 冲突：丢弃 staging，计 `snapshot_discarded`。
- 内存：发送端 snapshot buffer + 接收端 staging 各约一份该类型全量状态；`NodeConfig` 增加 `snapshot_sender_copy_bytes`、`snapshot_staging_limit_bytes`，超过则中止/丢弃并计 `snapshot_overflow`。600K 场景下快照可能占 ~2x 状态，作为可选项。

### 6.2 去重与序号

- Header 增加/启用 `sequence`（u64）：发送端每个数据/快照帧递增；接收端按来源记录 `last_sequence`，用于缺口统计（M4）。
- 对象级去重：ObjectStateStore 记录每个 `(type_id, object_id)` 的 `{schema_id, timestamp, sequence, source, payload}`；收到对象时，若 `timestamp` 更旧则丢弃并计 `rx_stale`；相同时间戳按 sequence 决胜。
- **对象所有权（已确认）**：每个 `(type_id, object_id)` 只有一个权威 publisher，store key 保持 `(type_id, object_id)`。若收到第二个 source，计 `rx_source_conflict`，按“最后写入”处理；本轮不支持多写者，后续如需多写者再给 key 加 source/priority。
- 快照 staging key 固定为 `(source, snapshot_id)`，不同 publisher 的 snapshot_id 不会互相覆盖；单写者下不同来源不应有重叠对象，若出现重叠按上述“最后写入 + 冲突计数”处理。
- Snapshot 与实时流并发：快照 staging 不直接改 store；End 时按上述规则合并，实时流中更新的对象胜出，避免双进程 demo 的 17 条重复。
- 时钟假设：timestamp 来自发送端 `system_clock`；跨节点时钟不保证同步时，以 sequence 为主、timestamp 为辅。文档明确该假设。

### 6.3 Delta baseline

- 引入内部 `ObjectStateStore`（O(1) `unordered_map<ObjectKey, ObjectState>`），替代 `retained_` 的线性 vector：
  - full publish / batch：写入最新 full payload；
  - delta：从 store 取 base，应用补丁，写回；store 始终保持最新 full 值；
  - delta 的补丁基准就是 store 中的最新 full 值；`publish_delta_typed<T>` 不接受调用方旧值。旧 `publish_delta(old,new)` 仅作为兼容重载：内部以 store base 为准，并用 `old_bytes` 做长度/指纹校验；不一致或没有 base 时回退 full publish，计 `tx_delta_fallback`。
  - snapshot：从 store 读取；
  - 有界：`NodeConfig.max_state_objects`/`max_state_bytes`，按 LRU/最旧 timestamp 驱逐。
- 订阅端 delta：`subscribe_delta` 的 cache 也用同一个 store；delta 到达但无 base 时，标记 `needs_snapshot` 并（限速）发送 `request_snapshot`，避免静默丢更新。
- 订阅端 baseline 的 `schema_id` 与 delta 的 `schema_id` 不一致时，不应用补丁；标记 `needs_snapshot` 并请求快照。对象被驱逐后，delta 回退 full publish；订阅端收到 full 对象后重置 baseline。
- 这一项同时修掉当前 `retain()` 的 O(n²) 线性查找和每次 publish 深拷贝问题；虽然本迭代不以性能为目标，但它是 M3 正确性的前提。

### 6.4 分片按 peer 隔离

- `FragmentAssembler::feed` 增加 `SourceKey` 参数（源 `Endpoint`，地址+端口；能拿到 NodeId 时用 NodeId）。
- pending key 改为 `(SourceKey, frame_id)`；`frame_id` 仍是发送端自增。
- 增加上限：`count <= kMaxFragments`（如 1024）、单帧总字节 <= `kMaxFrame`、每个 pending 组的 slice 总字节 <= `kMaxFrame`；超限丢弃并计 `rx_fragment_overflow`。
- 同一 frame_id 的重复/乱序/覆盖按现有逻辑处理；最终 CRC 校验整帧。

### 6.5 必测用例

- 100 个对象发布后，晚加入订阅者请求快照，只收到一次完整集合；回调顺序不要求，但无重复、无缺失。
- 快照过程中 publisher 继续发布：最终状态等于最新实时值；不存在“旧快照覆盖新值”。
- 两个 publisher 同时向同一 subscriber 发大帧（需要分片），frame_id 相同也不串包。
- 丢包/超时：Begin 后丢 Chunk、丢 End，staging 超时丢弃，应用不看到半成品。
- Delta after full：full 种下 baseline，连续 delta 后 snapshot 返回最新 full 值；late joiner 通过 snapshot + delta 正常。
- 有界状态：超过 max_state_objects 时驱逐最旧对象，metrics 可见。

## 7. M4：可靠性

- **序号/缺口**：每个发送端维护 `tx_sequence`，写入 Header；接收端按来源维护 `last_sequence`；缺口计 `rx_gaps`，连续缺口超过阈值（如 3）时对状态型 TypeId 触发一次限速 snapshot 请求。
- **请求重试**：SchemaRequest/SnapshotRequest 带 `request_id`；`request_id` 放在 SchemaRequest/SchemaResponse 和 SnapshotRequest/SnapshotBegin；SnapshotChunk/End 用 `snapshot_id` 关联。发送端维护 pending 表（key 为 `(peer, request_id)`），200ms 未响应重发，最多 3 次；响应带 `request_id` 匹配；迟到的重复响应直接丢弃并计 `rx_late_response`。ACK/NACK 可选，先用响应即 ACK。
- **Goodbye**：`Node::stop()` 通过控制面发送 `DiscoveryType::kGoodbye`；收到后立即标记 peer offline，不等 `peer_timeout`。
- **有界状态**：ObjectStateStore、`known_peers_`、`FragmentAssembler` pending、SchemaRegistry arena 都有上限或可配置容量；超限有 metric，不静默增长。
- **Packet loss 测试**：在测试里加一个 `LossyTransport` 包装（丢弃/重排/复制 datagram），验证快照恢复、delta 重同步、无崩溃、无无界内存。
- **指标**：`rx_gaps`、`rx_stale`、`rx_duplicates`、`rx_schema_miss`、`rx_decode_errors`、`snapshot_received/discarded/overflow`、`retry_count`。

## 10. 已做的决定（请检查）

1. **wire v0.2 干净断代**，不做 v0.1 双解码；所有节点一起升级。
2. **Packed 从 M1 起就是 tagged 格式**（packed 头 + 每字段 field_id/length/value）；M2 不换 wire 格式，`schema_wire_version` 保持 2。
3. **嵌套 struct 扁平展开**；M1 不做命名嵌套类型/递归 descriptor。
4. **M1 只支持基础类型元素的数组/序列**；struct 数组/序列推迟。
5. **复杂类型不做 batch/delta**；`publish_batch` 只对 fixed raw；delta 推荐 `publish_delta_typed<T>`，以 ObjectStateStore 为 baseline。
6. **全定长用 `kFixedRaw` 原始字节，含变长用 `kPacked`**；fixed 快路径不退化。
7. **FieldID = 点分名字段名的 FNV-1a32**；同 descriptor 内冲突拒绝；改名/重排视为不兼容。
8. **M2 默认值为零/空**；非零默认值后续。
9. **String 按不透明字节处理**（不强制 UTF-8）；只支持 little-endian。
10. **快照发送端和接收端各约一份副本**；通过 `snapshot_sender_copy_bytes`/`snapshot_staging_limit_bytes` 控制，超限中止/丢弃。
11. **M3 引入内部 ObjectStateStore**（O(1)、有界），但不暴露完整 ObjectStore/Dirty API；公开 ObjectStore 留给性能迭代。
12. **未知 schema_id**：packed 先做 tag 兼容解码，成功不丢帧；fixed raw exact schema 缺失则请求并丢弃。
13. **Snapshot 每对象携带 schema_id/timestamp/sequence**；Begin 不冻结单一 schema_id；End 必须校验 `staged_count == expected_count` 与 chunk_index 覆盖。
14. **`request_id` 放在 SchemaRequest/SchemaResponse 与 SnapshotRequest/SnapshotBegin**；SnapshotChunk/End 用 `snapshot_id` 关联。
15. **指纹按 descriptor 顺序、按 layout 归一化**：packed 不含 offset/name_offset，fixed raw 含 offset；远程同指纹 packed descriptor 保留本地版本。
16. **raw `publish` 增加 `SchemaId` 重载**；packed/多版本必须传精确 schema_id，payload 由调用方按 tagged 格式编码。
17. **已确认：单写者语义**。每个 `(type_id, object_id)` 只有一个权威 publisher；第二个来源计 `rx_source_conflict` 并按最后写入处理；store key 保持 `(type_id, object_id)`。

## 11. 风险与应对

| 风险 | 应对 |
|---|---|
| M1 反射/展开模板复杂度高 | 先写 `describe<Motor>`/`ExpandField` 的单元测试，再接入 Node；不支持的类型用 `static_assert` 明确报错 |
| packed/fixed 双路径导致行为分叉 | 用同一个 `ObjectCodec` 入口，fixed 只是走 raw 分支；测试同时覆盖两种 layout |
| Schema v0.2 断代影响现有 Demo | 一次性升级 examples/tests；在 README 标注协议版本；不保留旧节点 |
| 快照 staging 内存翻倍 | 配置上限 + 超限丢弃 + metrics；600K 场景默认关闭或减小 staging 上限 |
| 时钟不同步导致去重错误 | 以 sender sequence 为主、timestamp 为辅；测试用可控时钟 |
| 复杂类型分配/异常 | 冷路径允许标准库分配；decode 做边界检查，失败返回 false；不把异常暴露给调用方 |
| 指纹跨 ABI 不一致 | packed 指纹不含 offset；fixed raw 指纹含 offset，并明确 fixed 只保证同 ABI |

## 12. 已确认的范围与语义

1. **对象所有权：单写者**。每个 `(type_id, object_id)` 只有一个权威 publisher；第二个 source 计 `rx_source_conflict`，按最后写入处理；store key 保持 `(type_id, object_id)`。本轮不做多写者；后续如需，再给 key 加 source/priority。
2. **范围收口：按当前设计**。本轮不纳入：
   - struct 的数组/序列（`std::vector<Position>`、`Position[N]`）
   - 复杂类型的 batch/delta
   - 非零默认值
   - v0.1 节点互操作
   本轮只做 M1–M4 主路径：复杂类型（基础元素）、v0.2 tagged packed、Schema 版本/追加字段、原子快照/单写者去重、序号/重试/Goodbye。
